# راهنمای نصب نسخهٔ اصلاح‌شدهٔ «دارایی من»

این بسته برای همان Worker فعلی Cloudflare است. سایت یا دیتابیس جدید نساز. GitHub و نصب برنامه لازم نیست.

## اول فقط این سه کار را انجام بده

۱. در سایت فعلی از تنظیمات، «دانلود پشتیبان» را بزن.
۲. در Cloudflare دیتابیس فعلی را باز کن و **schema.sql جدید** را در Console اجرا کن. دستورها `CREATE ... IF NOT EXISTS` هستند؛ حساب‌ها و معاملات موجود حذف نمی‌شوند. اگر Console چند دستور را با هم قبول نکرد، هر دستورِ تمام‌شده با `;` را جدا اجرا کن.
۳. Worker فعلی ← Edit code: تمام کد قبلی را با **کل فایل worker.js جدید** جایگزین کن و Deploy بزن. سپس سایت را با Ctrl+Shift+R باز کن.

**worker.js خودش کل سایت و index.html را داخلش دارد.** برای روش نصب تو فقط worker.js و schema.sql لازم‌اند. لازم نیست index.html را جدا روی Cloudflare بارگذاری کنی. index.html برای ویرایش‌های بعدی و نصب جداگانهٔ فایل‌های استاتیک هم داخل بسته است؛ بازکردن آن با دوبار کلیک، سرور و API ایجاد نمی‌کند.

اگر قبلاً Binding استاتیک با نام ASSETS ساخته‌ای، این نصب تک‌فایلی اولویت را به HTML داخل Worker می‌دهد تا فایل قدیمی سایت نمایش داده نشود.

## تنظیمات ضروری Worker

در صفحهٔ Worker:

- Bindings: دیتابیس فعلی با Variable name دقیقاً `DB` متصل باشد.
- Settings ← Variables and Secrets: مقدار `APP_URL` همان آدرس HTTPS سایت، بدون `/` آخر باشد.
- `AUTH_SECRET`: نوع Secret؛ یک مقدار تصادفی قوی و حداقل ۳۲ کاراکتر. مقدار قبلی امن خودت را نگه دار. این مقدار را داخل فایل‌ها ننویس.
- تغییرها را Deploy کن.

Settings ← Trigger Events ← Cron Triggers:

- زمان‌بندی قدیمیِ هر ۵ دقیقه را به `* * * * *` تغییر بده؛ یعنی بررسی پس‌زمینه هر دقیقه.
- زمان‌بندی روزانهٔ `17 3 * * *` را نگه دار؛ برای تازه‌کردن فهرست بازارها است و بر اساس UTC اجرا می‌شود.

بدون Cron هم بازکردن سایت دریافت قیمت را شروع می‌کند. **هشدار ایمیلی وقتی سایت بسته است، به Cron نیاز دارد.** بررسی ایمیلی هر دقیقه است؛ اتصال ثانیه‌ای مرورگر به‌معنای ارسال ثانیه‌ای ایمیل نیست. اگر قیمت بین دو بررسی از هدف عبور کند و برگردد، عبور کوتاه ممکن است دیده نشود.

## بررسی قیمت‌ها

۱. سایت را باز کن و چند ثانیه منتظر بمان.
۲. بازار ← جست‌وجوی BTC: واحد باید **USDT** باشد، نه تومان. این قیمت بازار BTC/USDT است؛ دلار بانکی نیست.
۳. تتر داخلی باید تومان باشد؛ اگر نمایش ریال را انتخاب کردی، نرخ‌های داخلی ریالی می‌شوند. واحد رمزارزهای دیگر با این تنظیم عوض نمی‌شود.
۴. زمان و وضعیت زیر هر کارت را ببین. «قدیمی / تأخیردار» یعنی زمان خودِ قیمت قدیمی است؛ نه اینکه حتماً ارتباط سایت قطع است.
۵. دکمهٔ ↻ دوباره دریافت می‌کند. برای محافظت از API، درخواست‌های سراسری قیمت حداکثر حدود هر ۱۵ ثانیه تازه می‌شوند؛ کلیک‌های پشت‌سرهم الزاماً دادهٔ جدیدتری ندارند.

رمزارزها در صورت اتصال شبکه از WebSocket به‌روز می‌شوند؛ در قطع آن، دریافت دوره‌ای تقریباً هر ۱۵ ثانیه ادامه دارد. برای اتصال مجدد تلاش می‌شود. نرخ داخلی به انتشار API داخلی وابسته است؛ اگر آن API هنوز همان قیمت و همان زمان را منتشر کند، برنامه تاریخ قیمت را جلو نمی‌برد.

فهرست شامل تمام دارایی‌های فعال Spot با جفت USDT در پاسخ معتبر بایننس است؛ سقف ۵۰۰تایی و حذف بر اساس حجم معامله برداشته شده، نام‌های غیرلاتین هم پشتیبانی می‌شوند. تتر داخلی مستقل است. ارزهای فیات مثل EUR و TRY در بخش نرخ داخلی نمایش داده می‌شوند. جفت‌های تکراری و بازارهای متوقف‌شده دارایی جدا محسوب نمی‌شوند. برای سبک‌بودن صفحه، بازار ابتدا ۶۰ کارت می‌سازد؛ «نمایش بیشتر» و جست‌وجو روی کل فهرست کار می‌کنند.

نام سرویس‌ها در رابط کاربر نمایش داده نمی‌شود؛ زمان، واحد و وضعیت داده نمایش داده می‌شود.

## چرا بعضی نمودارها در ابتدا خالی هستند؟

- رمزارز: تاریخچهٔ واقعی بازار برای بازهٔ انتخابی دریافت می‌شود؛ نمودار کارت، بازهٔ ۲۴ ساعت است.
- داخلی: تاریخچه از انتشار واقعی قیمت‌ها پس از نصب این نسخه جمع می‌شود. در ابتدا ممکن است فقط یک نقطه باشد. تا دو نقطهٔ واقعی نباشد، نمودار ساخته نمی‌شود. این API در این پیاده‌سازی آرشیو درون‌روزیِ آماده برای گذشته فراهم نمی‌کند.
- تاریخچهٔ داخلی جدید جدا ذخیره می‌شود تا داده‌های قدیمی با واحد یا محاسبهٔ نادرست وارد نمودار جدید نشوند؛ داده‌های قبلی پاک نمی‌شوند.
- نمودار ارزش سبد: فقط ارزش‌هایی را نشان می‌دهد که واقعاً روی همین دستگاه ثبت شده‌اند. این نمودار شامل اثر خرید و فروش و تغییر قیمت است؛ نمودار بازدهِ خالص یا بک‌تست فرضی نیست. برای انتقال آن به دستگاه دیگر از پشتیبان استفاده کن.
- در نمودار، زمان از چپ به راست است. حرکت ماوس یا لمس، زمان و قیمت نزدیک‌ترین نقطه را در گوشه نشان می‌دهد. کلیدهای چپ و راست هم قابل استفاده‌اند.
- منحنی بین نقاط نرم شده؛ خودِ نقاط، زمان‌ها و قیمت‌ها تغییر نکرده‌اند.

## راه‌اندازی ایمیل — مرحله‌به‌مرحله

ایمیل برای ثبت‌نام با رمز، بازیابی رمز و ارسال هشدار لازم است. دیدن قیمت‌ها و ثبت محلی معاملات به ایمیل وابسته نیست.

۱. با Gmail خودت به https://script.google.com برو و **New project** را بزن.
۲. فایل Code.gs پیش‌فرض باز است. تمام کد آن را پاک کن؛ کل متن **Code.gs این بسته** را داخلش Paste کن و Save بزن.
۳. سمت چپ چرخ‌دندهٔ **Project Settings** را بزن. در قسمت **Script Properties**، گزینهٔ **Add script property** را بزن:
   - Property: دقیقاً `SECRET`
   - Value: یک متن تصادفی بلند. آن را در جای امن نگه دار؛ در مرحلهٔ ۸ به همان مقدار نیاز داری.
۴. به Editor برگرد. بالای صفحه از فهرست نام تابع‌ها **authorizeMail** را انتخاب کن و **Run** بزن. این تابع فقط مجوز ارسال ایمیل را درخواست می‌کند؛ به کسی ایمیل نمی‌فرستد. حساب خودت را انتخاب و مجوز همان پروژه‌ای را که ساخته‌ای تأیید کن. اگر محدودیت سازمانی اجازهٔ تأیید یا انتشار عمومی نمی‌دهد، از حساب شخصی مجاز یا سرویس ایمیل جایگزین استفاده کن.
۵. بالای سمت راست **Deploy ← New deployment** را بزن. کنار Select type چرخ‌دنده را بزن و **Web app** را انتخاب کن.
۶. تنظیم کن: **Execute as: Me** و **Who has access: Anyone**. سپس Deploy بزن.
۷. مقدار **Web app URL** را کپی کن؛ باید به `/exec` ختم شود. آدرس ویرایشگر یا `/dev` را برندار.
۸. به Cloudflare ← Worker فعلی ← Settings ← Variables and Secrets برو و دو **Secret** اضافه کن:
   - `MAIL_WEBHOOK_URL`: آدرس مرحلهٔ ۷.
   - `MAIL_WEBHOOK_SECRET`: دقیقاً مقدار SECRET مرحلهٔ ۳؛ بدون فاصلهٔ اضافه.
۹. Deploy بزن. در سایت یک ثبت‌نام با ایمیل واقعی خودت انجام بده و پوشهٔ Spam را هم ببین.

اگر در آینده Code.gs را عوض کردی: **Deploy ← Manage deployments ← Edit ← New version ← Deploy**. صرف Save کردن، نسخهٔ عمومی `/exec` را عوض نمی‌کند.

ارسال با سهمیهٔ حساب Gmail محدود است. هنگام قطع سرویس یا تمام‌شدن سهمیه، هشدار با فاصلهٔ افزایشی تا ۵ بار تلاش می‌شود؛ ورود گوگل از تنظیمات ارسال ایمیل جداست. هیچ رمز یا Secret نباید داخل HTML قرار بگیرد.

## فعال‌کردن دکمهٔ گوگل

دکمه در هر دو صفحهٔ ورود و ثبت‌نام وجود دارد؛ برای کارکرد آن باید OAuth حساب خودت تنظیم شود.

۱. به https://console.cloud.google.com برو؛ پروژهٔ خودت را ایجاد یا انتخاب کن.
۲. در **Google Auth Platform**، اطلاعات برنامه (Branding)، ایمیل پشتیبانی و Audience را تنظیم کن. اگر برنامه در حالت Testing است، Gmail خودت را در **Test users** اضافه کن. نام منوها ممکن است کمی متفاوت باشد.
۳. **Clients ← Create client ← Web application** را انتخاب کن. در رابط قدیمی این گزینه زیر **APIs & Services ← Credentials ← Create credentials ← OAuth client ID** است.
۴. **Authorized redirect URI** را دقیقاً این‌طور ثبت کن؛ به‌جای نمونه، دامنهٔ واقعی خودت را بگذار:

   `https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/api/auth/google/callback`

۵. Client ID و Client secret را در Cloudflare Worker ثبت کن:
   - `GOOGLE_CLIENT_ID`: Text
   - `GOOGLE_CLIENT_SECRET`: Secret
۶. `APP_URL` باید دقیقاً دامنهٔ همین redirect باشد. Deploy کن و ثبت‌نام با گوگل را امتحان کن.

خطای `redirect_uri_mismatch` یعنی آدرس مرحلهٔ ۴ با آدرس ارسالی سایت دقیقاً یکی نیست. ورود با گوگل بدون MAIL_WEBHOOK هم می‌تواند کار کند؛ ارسال هشدار ایمیلی همچنان به سرویس ایمیل نیاز دارد.

## معاملات و ارزش سبد

- خریدهای متعدد، فروش جزئی یا کامل، کارمزد و انتقال بین کیف پول‌ها ثبت می‌شوند.
- **قیمت و کارمزد ثبت معامله به تومان‌اند**؛ برای رمزارز، مبلغ واقعی تومانی معامله را وارد کن. نمایش بازار رمزارز مستقل و با USDT است.
- برای انتقال، کیف پول مبدأ و مقصد متفاوت را مشخص کن. قیمت انتقال اثری بر بهای خرید ندارد؛ در فیلد قیمت ۱ وارد کن. کارمزد انتقال به تومان در سود/زیان محقق‌شده کسر می‌شود؛ انتقالِ کارمزد به‌صورت کسر مقدار رمزارز مدل‌سازی نشده است.
- کنترل موجودی بر اساس تاریخ، ترتیب ثبت و کیف پول است. برای جابه‌جایی تاریخ خریدِ دارای فروش بعدی، کل ترتیب باید همچنان معتبر بماند.
- میانگین خرید و بهای باقی‌مانده با روش میانگین موزون محاسبه می‌شوند. سود/زیان باز و محقق‌شده جدا هستند.
- ارزش تومانی رمزارزها از قیمت USDT × تتر داخلی محاسبه می‌شود و تخمینی است. مبلغ خرید ثبت‌شدهٔ خودت با تغییر تتر بازنویسی نمی‌شود.
- اگر قیمت یک دارایی یا نرخ تبدیل موجود نباشد، جمع کامل و سود/زیان جاری «نامشخص» نمایش داده می‌شود. با قیمت قدیمی، وضعیت و علامت تقریب نمایش داده می‌شود.
- این نسخه دفترکل کامل بانکی، سفارش‌گذاری یا حسابداری مالیاتی نیست. تاریخچهٔ ساعتی معاملات قدیمی از فایل قبلی قابل بازیابی نیست؛ برای ثبت‌های جدید ترتیب ثبت در کنار تاریخ حفظ می‌شود.

## همگام‌سازی و حریم خصوصی

بدون ورود، داده‌ها فقط در همین مرورگر هستند. بعد از ورود، معاملات، کیف پول‌های ثبت‌شده، واچ‌لیست و هشدارها با حساب همگام می‌شوند. اگر دو دستگاه هم‌زمان تغییر دهند، ذخیرهٔ قدیمی رد می‌شود؛ پنجرهٔ انتخاب نسخه می‌آید و چیزی بی‌صدا روی نسخهٔ جدید نوشته نمی‌شود. انتخاب «نسخهٔ این دستگاه» همهٔ دادهٔ حساب را با همین نسخه جایگزین می‌کند؛ قبلش دکمهٔ پشتیبان در همان پنجره در دسترس است.

خروج از حساب، دادهٔ محلی را پاک نمی‌کند. در دستگاه مشترک پس از خروج، از تنظیمات «حذف داده‌های این دستگاه» را بزن. پشتیبان JSON حاوی جزئیات مالی است و رمزگذاری نشده؛ آن را خصوصی نگه دار.

## اگر هنوز قیمت دریافت نشد

- روی دامنهٔ Worker تست کن؛ فایل HTML محلی API ندارد.
- `https://YOUR-SITE/api/health`: مقدار database باید true باشد؛ google و email فقط وجود تنظیمات را نشان می‌دهند، نه تأیید عملی سرویس.
- `https://YOUR-SITE/api/prices?refresh=1`: وجود items و زمان‌ها را بررسی کن. feeds.crypto.ok و feeds.domestic.ok وضعیت آخرین دریافت را نشان می‌دهند.
- اگر پیام دیتابیس آمد، Binding با نام بزرگ DB را چک کن و schema.sql جدید را روی همان دیتابیس اجرا کن.
- اگر دریافت موفق است اما زمان داخلی قدیمی است، خودِ منبع هنوز نرخ جدید منتشر نکرده است. رفرش، زمان واقعی آن را تغییر نمی‌دهد.
- Worker ← Observability / Logs را بررسی کن. خطای 1102 یا سقف CPU/سهمیه به محدودیت پلن مربوط است؛ دریافت بزرگ بازار و هش رمز با PBKDF2 صد هزار دور باید روی پلن واقعی خودت بررسی شوند. برای کاهش امنیت، تعداد دور پیش‌فرض پایین آورده نشده است.

## دامنهٔ آزمایش انجام‌شده

API داخلی، فهرست بازارها، تیکر و تاریخچهٔ بایننس در محیط بررسی پاسخ HTTP 200 دادند. منطق سرور با پاسخ‌های واقعی ذخیره‌شده، دیتابیس SQLite سازگار با شکل D1، و درخواست‌های آزمایشی بررسی شد. رابط در مرورگر دسکتاپ و عرض موبایل، ثبت معامله، وجود دکمهٔ گوگل و نمایش tooltip بررسی شد. قطع یک منبع، تعارض نسخه، رد دسترسی بدون حساب، محاسبهٔ فروش و انتقال و جلوگیری از فروش بیش از موجودی نیز بررسی شدند.

این بررسی، اجرای نهایی روی حساب Cloudflare تو، اتصال WebSocket از شبکهٔ تو، ارسال Gmail واقعی یا ورود Google با Client ID حساب تو را تأیید نمی‌کند؛ این‌ها پس از اعمال تنظیمات باید روی آدرس خودت آزمایش شوند. ارسال ایمیل ضمانت exactly-once مطلق ندارد؛ شناسهٔ ارسال و قفل، تکرار معمول را کاهش می‌دهند، اما قطع سرویس در فاصلهٔ ارسال ایمیل و ثبت نتیجه هنوز ممکن است تکرار ایجاد کند.
